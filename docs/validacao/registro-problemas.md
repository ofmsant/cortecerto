# Registro de problemas de usabilidade e critérios de correção

## 1. Níveis de gravidade

| Nível | Descrição |
|---|---|
| Crítico | Impede concluir uma tarefa, deixa dado errado salvo sem o participante perceber, ou leva a ação irreversível não desejada |
| Alto | O participante só conclui com ajuda direta, ou perde mais de 30 segundos por causa do problema |
| Médio | O participante hesita, erra e corrige sozinho, ou demonstra confusão sem perder a tarefa |
| Baixo | Incômodo estético ou comentário de preferência, sem efeito na tarefa |

## 2. Critérios para decidir as correções

1. Problemas críticos e altos que afetam os critérios de aprovação são corrigidos antes da segunda rodada.
2. Problemas médios são corrigidos se a correção for pequena e dentro do escopo do MVP.
3. Problemas baixos ficam registrados e só são tratados se sobrar tempo.
4. Uma correção que exija uma funcionalidade fora do escopo não é feita. O pedido é registrado como "fora do escopo" e fica para uma versão futura.
5. Quando houver dúvida sobre a causa, ouvir novamente o participante ou observar de novo, em vez de supor.
6. Cada correção vira um commit próprio, com mensagem que descreva o problema real, e o hash é registrado na tabela.
